# 设计思路 · 个人工作台

## 1. 产品定位

**面向白领职场的个人办公工作台**。不是项目管理工具，不是团队协作平台，而是"一个人每天打开就能用"的私人桌面助手。

### 三个关键决策

| 维度 | 决策 | 原因 |
|---|---|---|
| 平台形态 | **Web 优先** | 浏览器是白领最现成的运行环境，无需安装、跨系统。不选 App 形态是因为办公场景天然在电脑+浏览器上 |
| 商业模式 | **纯工具** | 不做账号体系、不做云同步、不做订阅。工具就是工具，买了即用，用完即走 |
| 数据归属 | **本地优先** | 数据存在用户自己设备的浏览器里，不上云、不被采集。隐私和便携性的取舍选择信任用户本机 |

## 2. 为什么是这 6 个模块

办公白领的一天，本质上循环做四件事：**记 → 做 → 存 → 报**。

```
记（输入）        做（执行）        存（沉淀）        报（输出）
 任务清单  ──→   日程时间  ──→   AI 知识库  ──→  工作总结
 会议速记  ──→   任务清单  ──→   会议速记   ──→  报表助手
```

六个模块刚好覆盖这条链：

1. **任务清单** —— 一切的起点。按时间颗粒度切分（日/周/月/自定义），对应白领真实的工作节奏
2. **AI 知识库** —— 文档归宿。办公会产生大量 Word/Excel/PDF，需要一处归档+检索的地方
3. **报表助手** —— 数据→呈现的中间环节。从零散数据到图表到结论
4. **日程时间** —— 把任务放进时间轴。会议、专注块、截止提醒，与任务清单联动
5. **会议速记** —— 会议是白领最高频的"输入场景"。决议、待办、风险需要当场记下，待办回流任务清单
6. **工作总结** —— 闭环输出。汇总本期任务、会议、产出，生成日报/周报/月报

## 3. 模块类型的抽象

所有模块归为两类：

- **`todo` 型**：有完成状态（勾选）、有优先级分组（每日/每周、会议/专注）。任务清单、日程时间
- **`note` 型**：无完成状态，按分类标签组织，正文是富文本。知识库、报表、会议速记、工作总结

这样分类的好处：渲染逻辑、交互逻辑、统计逻辑各写一套，6 个模块复用两套逻辑，代码量减半。

## 4. CONFIG 驱动的设计

模块不是硬编码的，而是数据驱动的。`CONFIG.modules` 是一个数组，每个元素描述一个模块的全部信息：

```
{ key, name, icon, color, type, desc,
  priorities / moods,   // 分组
  fields: [...]         // 字段定义
  seed: [...]           // 初始示例数据
}
```

**为什么这样设计**：加一个新模块不需要写任何渲染代码，只需要在 CONFIG 里加一段配置 + 定义字段。字段类型只有 3 种（text/textarea/select），覆盖了 90% 的办公场景。这意味着即使不会写代码的人，照着模板抄一段也能加模块。

## 5. 主题系统

颜色不散落在 CSS 里，而是全部抽到 `:root` 的 CSS 变量里：

- 页面表面三色（底色/卡片/嵌套）
- 文本三层级（主/次/弱）
- 主色 + 5 个模块色（色轮轮转，新模块自动取下一个未用的色）
- 危险色 + 侧栏深色面板

**换肤 = 改 :root**。一处改色，整站换肤。模块色用 `--module-1` ~ `--module-5`，与 CONFIG 里的 `color:"var(--module-N)"` 对应，保证视觉一致性。

## 6. 单文件交付的取舍

选择把 HTML / CSS / JS 全塞进一个文件（~97KB），而不是拆分多文件：

| 优点 | 代价 |
|---|---|
| 拷贝即用，不依赖文件相对路径 | 单文件偏大，阅读需折叠 |
| 不会因为路径错误而样式丢失 | 改动需在单文件内定位 |
| 可以邮件附件、U盘、网盘任意分发 | 不适合多人协作开发 |

对个人工具而言，分发便利 >> 协作便利，所以选单文件。

## 7. AI 能力的预留

当前版本是纯本地工具，AI 相关字段（如"AI 关键点"、"AI 辅助建表"）是**预留位**——字段已在 CONFIG 里定义，UI 已渲染，但实际 AI 计算未接入。

设计意图：先把数据结构和交互跑通，AI 作为后续可插拔层。接入时只需在对应字段写入时调用 AI 接口填值，不影响现有数据结构。

## 8. 不做的事

- 不做账号系统（纯工具，不需要登录）
- 不做多端同步（数据本地，换设备即换数据）
- 不做团队协作（个人工具，非团队工具）
- 不做复杂权限（只有自己一个人用）
- 不做移动端 App（Web 优先，手机浏览器也能开）

这些"不做"是有意的边界，保证工具轻、快、稳。
